Why it is vendored
  Upstream boring.notch shipped a prebuilt, ad-hoc signed
  MediaRemoteAdapter.framework and an unsigned MediaRemoteAdapterTestClient
  with no source or build step (security card #38). This copy is the exact
  upstream source at the commit above, built by the "MediaRemoteAdapter"
  framework target in boringNotch.xcodeproj and signed with the app.

What is included (unmodified)
  bin/mediaremote-adapter.pl    -> mediaremote-adapter.pl
  include/MediaRemoteAdapter.h  -> Sources/include/
  src/adapter, src/private,
  src/utility                   -> Sources/src/
  src/test/NowPlayingTest.h     -> Sources/src/test/ (imported by adapter/test.m)

What is intentionally left out
  src/test/main.m, src/test/NowPlayingTest.m (the MediaRemoteAdapterTestClient
  executable). The app never runs the adapter's "test" function, so no test
  client is built or shipped.

umbar additions (not upstream, upstream files above stay unmodified)
  Sources/umbar/UmbarParentWatchdog.m
    Constructor that runs when perl loads the framework. If
    UMBAR_ADAPTER_PARENT_PID is set, it watches that pid (kqueue NOTE_EXIT
    via a dispatch source) and _exits when the app is gone, so the stream
    child cannot be orphaned by quit, SIGTERM, SIGKILL or a crash (card #57).
    Without the variable it does nothing.

Runtime contract
  The framework is embedded in Contents/Frameworks but NOT linked into the app,
  so it never loads into the app process. It is loaded only by /usr/bin/perl
  running mediaremote-adapter.pl, and only when the user enables
  "Use system Now Playing" in Settings > Media (off by default).

Updating
  1. git -C <clone> checkout <new tag>; diff against this directory.
  2. Re-copy the files listed above; update Tag/Commit here.
  3. Check CMakeLists.txt upstream for new sources/frameworks and mirror them in
     the MediaRemoteAdapter target build settings.
